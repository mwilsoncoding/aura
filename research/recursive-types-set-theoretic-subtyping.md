# Recursive Types and Set-Theoretic Subtyping

Research completed 2026-09-29. This report distinguishes formal results from implementation evidence. It does not recommend adopting any of the surveyed designs.

## Findings

There is no single result covering unrestricted recursive type equations combined with union, intersection, and complement. The results below concern specific recursive representations and well-formedness conditions. In particular, “guarded,” “positive,” and “productive” are not interchangeable: guarding/contractiveness constrains recursive cycles to pass through constructors; positivity constrains variance through operators such as complement and function domains; neither condition by itself promises that a type is inhabited.

### Semantic subtyping decision bound

Gesbert, Genevès, and Layaïda formalize semantic subtyping over base, product, and function types, union, complement, and recursive `μ` types; intersection is defined from complement and union. Their relation is set inclusion, equivalently emptiness of the intersection of the left type with the complement of the right. Thus the paper's subtype algorithm also gives an emptiness decision procedure for its type algebra. ([Paper, §§2.1–2.2.2, Corollary 5.4](https://doi.org/10.1145/2812805); [author manuscript](https://inria.hal.science/hal-00848023/file/article.pdf))

The result is **an EXPTIME upper bound**, not an EXPTIME-completeness result: Lemma 5.5 gives time $2^{O(|\tau_1|+|\tau_2|)}$. The proof translates types linearly to formulas and uses an exponential-time satisfiability procedure for its tree logic (§5.4). This bound applies to the paper's formal algebra, including its polymorphic extension; it is not a measured runtime bound for a production compiler. ([Paper, §5.4, Lemma 5.5](https://doi.org/10.1145/2812805))

The result has material restrictions. Negation may only apply to closed types, arrow operands must be closed, and every recursive-variable occurrence must be separated from its binder by a product or arrow constructor. The paper rejects `μv. 0 ∨ v` as unguarded and also rejects `μv. 0 → ¬v` under its closedness restrictions. These rules make the type interpretation well-founded; they do not establish decidability for arbitrary recursive equations with variables under unrestricted Boolean operators or variance positions. The core grammar is based on products and functions (with XML tree types treated as regular tree languages), not a general named-record, row-polymorphic, or variant declaration system. ([Paper, §§2.1–2.2.2](https://doi.org/10.1145/2812805))

### Regular, contractive coinductive types

Schimpf, Wehr, and Bieniusa's 2026 arXiv preprint models recursive types as potentially infinite trees read coinductively. It requires **regularity** (finitely many distinct subtrees) and **contractiveness** (each infinite branch contains infinitely many `×` or `→` constructors). The paper identifies regularity as crucial to subtyping decidability and contractiveness as excluding equations such as `t = t ∨ t` and `t = ¬t`. This is a regular-tree/equi-recursive account, not a least-fixed-point solution of arbitrary set equations; its admissibility criterion is not simply positivity. ([Preprint v1, §3.1.1](https://arxiv.org/abs/2603.22032v1))

The preprint proves type checking decidable for its formal system (Sections 3.5 and B), using generated subtyping constraints and a terminating tallying procedure. It does **not state an asymptotic complexity class** for that procedure in the cited result. Its formalization has union, intersection, and negation, and its authors report an independent Etylizer implementation. However, the type language of Erlang itself only permits intersections at the top level of a function specification and has no negation syntax; negation is useful internally during analysis. The 2026 manuscript also says non-regular polymorphic types are the notable excluded class. ([Preprint v1, §§3.1.1, 3.5, 6](https://arxiv.org/abs/2603.22032v1); [Etylizer source at the paper-era revision](https://github.com/etylizer/etylizer/tree/574f1a13e04ab266756d3d0dbb4c88b2cd5745be))

The earlier, peer-reviewed Erlang paper gives a concrete recursive tagged-tree type and explains the regular/contractive restriction. It excludes the nested polymorphic type `perfect(A) = A | perfect({A,A})`, whose recursive argument changes at each unfolding. That is evidence about this formalization's boundary, not a theorem that such types are undecidable in every system. ([Schimpf et al., IFL 2022, §§2.2–2.3 and 3.1.1](https://doi.org/10.1145/3587216.3587220); [author preprint](https://arxiv.org/abs/2302.12783v2))

### First-party implementation evidence

CDuce's official manual supports union, intersection, and difference (complement relative to `Any` can be written as a difference). It allows mutually recursive aliases only when every cycle crosses a type constructor; Boolean connectives do not count as constructors. The manual also imposes a right-linearity restriction on recursive sequence concatenation. These are implementation-language well-formedness rules, not a complexity theorem, and the manual does not state a separate positivity condition. ([CDuce manual, “Boolean connectives”](https://www.cduce.org/manual_types_patterns.html#bool); [recursive types](https://www.cduce.org/manual_types_patterns.html#recurs); [sequences](https://www.cduce.org/manual_types_patterns.html#seq))

The pinned CDuce implementation revision `552553bac0b60717531e36928f73551d3dc7feae` represents Boolean operations for records as well as products, XML, and functions. Its subtype operation is implemented as `is_empty (diff d1 d2)`, matching the semantic reduction above. This demonstrates an implemented route for record Boolean types; source inspection alone supplies no asymptotic bound for that implementation. ([`types/types.ml`, record Boolean representation](https://gitlab.math.univ-paris-diderot.fr/cduce/cduce/-/blob/552553bac0b60717531e36928f73551d3dc7feae/types/types.ml#L397); [Boolean operations](https://gitlab.math.univ-paris-diderot.fr/cduce/cduce/-/blob/552553bac0b60717531e36928f73551d3dc7feae/types/types.ml#L453); [emptiness and subtyping](https://gitlab.math.univ-paris-diderot.fr/cduce/cduce/-/blob/552553bac0b60717531e36928f73551d3dc7feae/types/types.ml#L1082))

The independent Etylizer implementation likewise has separate modules for recursive types, Boolean types, tuples, and maps. Its authors state that the prototype supports Erlang's type language and most term-level constructs; the paper's conclusion notes map/record support but leaves its detailed treatment out of the formal presentation. Therefore this is useful implementation evidence, not a proof about arbitrary recursive record equations. ([Etylizer recursive types](https://github.com/etylizer/etylizer/blob/574f1a13e04ab266756d3d0dbb4c88b2cd5745be/src/erlang_types/ty_rec.erl); [Boolean types](https://github.com/etylizer/etylizer/blob/574f1a13e04ab266756d3d0dbb4c88b2cd5745be/src/erlang_types/ty_bool.erl); [maps](https://github.com/etylizer/etylizer/blob/574f1a13e04ab266756d3d0dbb4c88b2cd5745be/src/erlang_types/ty_map.erl); [2026 preprint, §§4 and 6](https://arxiv.org/abs/2603.22032v1))

## Implications for Aura

These sources leave several design choices open; they do not select among them:

- Specify whether recursion denotes least/greatest fixed points of sets, or equality with a regular infinite type tree. The semantics matters once recursive variables occur under complement or contravariant function positions.
- State separately whether recursive occurrences must be positive, constructor-guarded/contractive, regular, or some combination. A constructor guard prevents unproductive unfolding syntax but does not ensure a nonempty type.
- State whether recursive aliases may grow type arguments, as in `perfect(A)`, and whether recursive occurrences under complement or function domains are admitted.
- Define records and variants precisely (closed versus open rows, optional fields, constructor tags, and field variance) before transferring a result proved for products or a particular record representation.
- If a complexity target matters, identify the exact type grammar and representation. The cited $2^{O(n)}$ theorem is for the 2015 formal fragment; the Erlang preprint establishes decidability under regularity/contractiveness but does not supply a matching complexity bound.

## What Is Not Established

None of these sources proves decidability or a complexity bound for unrestricted recursive Boolean type equations. The EXPTIME theorem does not establish EXPTIME-hardness, and it should not be generalized to arbitrary named records, open rows, or every variant calculus. The Erlang result does not give an asymptotic bound for Etylizer and excludes non-regular recursive types; the CDuce implementation and manual do not state the complexity of their implementation's emptiness procedure. Conversely, these sources do not establish that unrestricted recursive Boolean types are undecidable: those systems either restrict the fragment or leave that question outside their stated results.
