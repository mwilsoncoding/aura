# Domain Docs

Before exploring, read the relevant root `CONTEXT.md`, or `CONTEXT-MAP.md` and its relevant context files, plus applicable ADRs in `docs/adr/`.

If these files don't exist, proceed silently. Create them lazily when terms or decisions are resolved; don't suggest creating them upfront.

This repo uses a single-context layout: `CONTEXT.md` at the root and ADRs in `docs/adr/`.

Use glossary terminology in issue titles, proposals, hypotheses, and tests. If a needed term is missing, reconsider whether it's project language or note a glossary gap. Surface conflicts with existing ADRs rather than silently overriding them.
